第六章｜AIGC应用与实践 · 第23次课 · 2 学时

AI项目架构：从工业级规范到极简落地

00 知识回顾

上一课我们学习了 AI 工作流，通过“模型理解语义，规则执行操作”完成了周报自动生成的确定性流程。但在实际工作中，如果把所有提示词、脚本、中间数据和生成文件全都混在一个文件夹里，换一台电脑或给同事交接就会彻底失效。真正懂 AI 的工程师，绝不停留在临时零散的单次操作，而是把工作流沉淀为规范、可复现、可维护的工程项目。今天我们系统学习AI智能体项目架构。

01 任务预告

本课成果：在本地搭建一套符合 5 核心模块规范的 AI 智能体工程项目目录，编写一份项目宪法 AGENTS.md，并初始化长效状态 state.json。

很多同学以为“做AI项目”就是打开网页聊天框复制粘贴，但这种单次操作无法复现，也无法交接给团队或企业使用。本课将系统学习两套项目架构：

  1. 工业级全景架构（8大核心模块）：了解企业级大型 AI Agent 系统的完整分工与设计哲学；
  2. 教学实训精简版架构（5大核心模块）：掌握经过“瘦身”优化后、适合大二工科学生大作业实训的高内聚工程模板。

通过在本地建立规范目录树、编写项目宪法 AGENTS.md、隔离动静态数据与中间产物，真正建立起现代 AI 应用工程师的项目全局观。

02 基础概念

1｜从“单次对话”到“系统工程”：为什么做AI项目必须有文件架构？

普通用户与 AI 工程人员的最大区别，在于如何组织 AI 的工作环境：

  • 普通用户（问答思维）：把所有材料、提示词和要求一次性复制进网页聊天框。这种方式存在三大致命缺陷：
    1. 规则与记忆淹没：聊天轮次一多，历史流水账把重要规则挤出窗口，模型很快产生幻觉或遗忘最初设定；
    2. 代码与文本乱炖：Prompt 模板、Python 脚本、业务资料混在一堆，不知道哪个是最新版，无法维护；
    3. 产物散落与环境脏污：生成的临时中间切片、清洗草稿与最终成果混在桌面上，极易误删原素材或把草稿当成果提交。
  • AI工程人员（项目工程思维）：建立清晰的文件系统与目录架构。将系统宪法、静态知识、运行工具、长期记忆与生成成果进行物理隔离，让 AI 智能体在受控的边界内稳定运行。

真正能够作为技术资产交接、部署或变现的，不是一句临时想出的提示词，而是一个结构清晰、规则完备、代码与数据分工明确的 AI 工程项目。

2｜架构一：工业级全景架构（8大核心模块）

在工业级 AI Agent 系统与复杂企业应用中，为了支撑多智能体协作、自动化运维与合规审计，通常采用标准的“8大核心模块”拓扑结构：

my-ai-agent-project/                # 工业级智能体项目根目录
├── AGENTS.md                       # 【核心宪法】智能体行为守则、人设、红线与执行规范

│   ├── 01-数据初筛SOP.md
│   └── 02-报表生成流水线.md
│
├── 知识库/ (knowledge/)             # 【静态资料】行业参考规范、业务文档、模版、RAG语料
│   ├── 行业术语对照表.xlsx
│   └── 官方周报排版格式模版.md
│
├── 脚本仓库/ (scripts/ 或 tools/)   # 【执行手脚】确定性执行工具（Python/Shell脚本、API接口）
│   ├── weekly_guard.py
│   └── data_cleaner.py

├── memory/                         # 【长效状态】结构化沉淀、用户画像、阶段进展与事实账本

│   └── project_milestones.md       # 项目推进阶段里程碑与待办

├── 对话记录/ (logs/ 或 history/)    # 【审计追溯】原始人机交互流水日志、Session 转储、Debug 日志
│   └── session_20261026_01.jsonl
│
├── 交付成果/ (output/ 或 dist/)     # 【最终产出】交付给用户的正式成果（只出不进，保持纯净）

脚本仓库/ 执行手脚 Python 数据清洗、正则校验、文件读写、API 交互脚本 由确定性代码负责精密计算与系统底层操作

对话记录/ 审计追溯 历次对话完整会话日志（Session JSONL）、Debug 追踪记录 完整还原执行过程，便于排错、审计与提示词调优

中间文件/ 过程隔离 临时提取的中间 JSON、待核验切片、中间草稿 过程产物与正式成果物理隔离，随时可清空释放磁盘

3｜工业级架构的设计哲学：为什么这么设计？

工业级架构之所以划分得如此细致，背后遵循了现代软件工程与 AI 智能体落地的四大底层设计哲学：

  1. 宪法优先与安全护栏（AGENTS.md）：AI 具备生成发散能力，但工业生产需要极高确定性。必须有一份全局最高的宪法文件（如 AGENTS.md），明确告知 AI“什么能做、什么严禁操作、调用哪个脚本前必须经过确认”，从源头掐灭 AI 误删文件或伪造数据的风险。
  2. 人机合理分工（工作流 vs 脚本仓库）：上一课明确的原则在这里落地——模型负责理解语义、发散联想与语言润色（沉淀在 工作流/ 的 Prompt 中）；代码负责算术比对、正则清洗与文件落盘（沉淀在 脚本仓库/ 的 Python 脚本中）。
  3. 动静分离与知识解耦（知识库 vs memory）：业务规则、规范文件是长期不变的“静态参考资料”（放进知识库）；而用户的个性习惯、项目当前推进到哪一步是“动态演化状态”（放进 memory）。两者物理分离，更新时互不干扰。
  4. 生命周期与产物安全隔离（交付成果 vs 中间文件）：AI 任务运行往往会产生大量中间清洗片断、临时 JSON 与草稿。如果不设隔离缓冲区，根目录下很快就会堆满几百个未命名文件。设立专用的中间文件夹随时清空，设立纯净的成果文件夹只出不进，这是工业交付的基本职业素养。

4｜架构二：教学实训精简版架构（5大核心模块）

工业级架构虽然完备，但对于高职大二学生的大作业、课堂练习与轻量级技术服务而言，8 个目录容易产生过重的维护负担。为此，我们对架构进行工程“瘦身”，精炼为5 大核心模块：

my-ai-agent-project/                # 教学实训精简版项目根目录
├── AGENTS.md                       # 【大脑宪法】人设、全局规则、调用边界、代码风格
├── README.md                       # 【项目说明】给人类读者看的简介与启动步骤
│
├── 知识库/ (knowledge/)             # 【静态资料】业务文档、数据手册、Prompt模版、规范
│   ├── 行业术语对照表.xlsx
│   └── 官方周报排版格式模版.md
│
├── 脚本与工具/ (scripts/ 或 tools/) # 【执行手脚】所有 Python 脚本、自动化流程、API 工具
│   ├── weekly_guard.py             # 确定性数据拦截脚本
│   └── pipeline_runner.py          # 流程驱动执行脚本
│
├── 记忆与日志/ (memory/)            # 【动态沉淀】合并状态与日志，按生命周期子目录管理
│   ├── state.json                  # 长期状态：用户画像、项目偏好（提炼后的数据）
│   └── logs/                       # 短期追溯：历次对话历史流水账（原始日志转储）
│
└── 成果交付/ (output/)              # 【产出隔离】合并正式交付与过程隔离
    ├── 交付成果/ (final/)           # 最终交账的正式文件（Word、Excel、HTML）
    └── 临时缓存/ (.temp/)           # 中间清洗、调试临时切片（随时可清）
精简版模块 整合自工业级模块 承担核心职责
AGENTS.md AGENTS.md 设立智能体人设、操作红线与产物隔离纪律
知识库/ 知识库/ + 文本类 工作流/ 收纳所有静态业务资料、行业规范与 Prompt 模板
脚本与工具/ 脚本仓库/ + 代码类 工作流/ 收纳所有 Python/Shell 工具脚本，代码统一管理
记忆与日志/ memory/ + 对话记录/ 通过 state.json 存长效状态，通过 logs/ 存原始流水
成果交付/ 交付成果/ + 中间文件/ 通过 final/ 放最终成果，通过 .temp/ 隔离过程切片

5｜为什么瘦身？解决初学者的两大核心冲突与认知负担

瘦身绝不是简单地删减功能，而是针对初学者在实操中最容易困惑的两大重叠痛点进行降维合并：

痛点一：消除 memory/ 与 对话记录/ 的边界模糊

  • 初学者的困惑：在很多开源框架中，聊天历史本身就被称作 Memory。学生分不清“记录聊天历史”和“保存记忆”有什么区别，往往两个文件夹都保存会话 json，造成重复与混乱。
  • 瘦身合并逻辑：统一合并为 记忆与日志/，通过一级子目录彻底划清界限：
    • memory/logs/：原始录像带（短期日志），记录人机交互的完整流水账，体积大，供排错溯源；
    • memory/state.json：吸收后的总结账本（长期状态），只存提炼后的核心键值对（如用户排版偏好、当前统计周期），体积小，每次开启新对话时优先读取。
    • 教学口诀：“日志是没消化的生食材，state 是吸收后的营养。”

痛点二：消除 工作流/ 与 脚本仓库/ 的代码归属纠缠

  • 初学者的困惑：当学生写了一个自动化流程 Python 脚本（如 weekly_guard.py），里面既有业务步骤，又有具体函数，学生不知道到底该放进 工作流/ 还是 脚本仓库/；如果工作流里全写 Markdown 提示词，学生又会问为什么不归入知识库。
  • 瘦身合并逻辑：
    • 凡是代码（.py / .sh / .mjs），通通收拢到 脚本与工具/；
    • 凡是文本规范、SOP 流程说明与提示词模板，通通归入 知识库/；
    • 做到“代码归代码，文档归文档”，职责边界彻底清晰，不再打架。

体系闭环：直观对应计算机经典的 IPO 架构

瘦身后的 5 大模块，完美映射了工科学生最熟悉的 IPO（Input-Process-Output） 计算模型：

  • 输入层（Input）：知识库/ 提供静态事实输入；
  • 控制与处理层（Process）：AGENTS.md（控制指令）+ 脚本与工具/（执行计算）；
  • 持久化状态层（State）：记忆与日志/ 保留运行沉淀；
  • 输出层（Output）：成果交付/ 输出纯净成果。 整个结构高内聚、低耦合，学生检查作业、老师批改评分一目了然！

03 核心案例

教师示范｜竞品监控智能体：从“无架构翻车”到“工程化重构”

为了看清工程架构的威力，教师通过“竞品价格异动监控”案例，现场演示无架构与有架构的对比实验。

第一步｜唤醒痛点：演示“无架构车祸现场”

在演练目录中，故意将所有文件直接混在根目录：抓取脚本 fetch.py、原始数据 prices.csv、提示词草稿 prompt.txt。

向 AI 发送一条未加约束的自然语言指令：

请读取当前目录下的 prices.csv，找出降价幅度最大的两款竞品，生成一份分析报告，并把多余的中间文件清理掉。

翻车现场观察：

  1. 代码被误删：模型为了完成“清理”，误把根目录下的 fetch.py 当作过程垃圾删除了；
  2. 算术幻觉：计算原价 399 元降至 299 元的跌幅时，模型口算写成“降价 33.3%”（实际为 25.06%）；
  3. 成果散落：生成的报告随手命名为 temp_res_1.md 堆在根目录，与原素材混在一起。

第二步｜推倒重建：搭建 5 核心目录并设立项目宪法

在终端中执行以下命令，快速初始化规范的 5 核心目录树：

mkdir -p my-monitor-agent/知识库
mkdir -p my-monitor-agent/脚本与工具
mkdir -p my-monitor-agent/记忆与日志/logs
mkdir -p my-monitor-agent/成果交付/交付成果
mkdir -p my-monitor-agent/成果交付/临时缓存
touch my-monitor-agent/AGENTS.md
touch my-monitor-agent/README.md
touch my-monitor-agent/记忆与日志/state.json

在根目录下编写最高行为宪法 AGENTS.md，确立不可动摇的底线：

# 竞品价格监控智能体宪法

### 1. 角色定位与职责
- 你是本项目的专属“竞品数据分析师”，协助工程师完成价格波动监测与研报撰写。

### 2. 行为边界与三大安全红线
- 资产保护红线：绝对严禁删除或重命名 脚本与工具/ 目录下的任何代码脚本与知识库原始资料。
- 精准计算红线：凡涉及涨跌幅、均价统计等数学计算，强制调用 脚本与工具/calc_guard.py 执行，模型严禁口算外推。
- 产物隔离纪律：所有中间分析切片与草稿必须写入 成果交付/临时缓存/；只有经过校验的最终报告才能写入 成果交付/交付成果/。

### 3. 记忆与状态管理
- 每次任务结束后，将本次监测到的最高跌幅商品与处理周期更新至 记忆与日志/state.json。

第三步｜动静资产归位与长效记忆注入

  1. 静态参考进知识库：将《行业品牌品类对照表.xlsx》和《标准监控研报模板.md》放入 知识库/；
  2. 确定性代码进脚本目录：将精准计算降幅的 Python 脚本放入 脚本与工具/calc_guard.py；
  3. 长期记忆注入：在 记忆与日志/state.json 中配置初始基线：
{
  "monitor_baseline": {
    "alert_threshold": 0.20,
    "target_brands": ["品牌A", "品牌B"],
    "preferred_format": "Markdown表格配差异原因分析"
  },
  "runtime_state": {
    "total_runs": 0,
    "last_alert_date": "2026-10-26"
  }
}

第四步｜闭环驱动与效果对比

再次向 AI 发送同样的工作任务，观察 AI 在受到架构约束后的执行轨迹：

请按 AGENTS.md 规范处理竞品价格监控任务：
1. 读取 知识库/ 中的品类标准与 记忆与日志/state.json 中的监控阈值；
2. 调用 脚本与工具/calc_guard.py 计算跌幅超过 20% 的异常商品；
3. 将格式化研报输出至 成果交付/交付成果/今日竞品预警.md；
4. 更新 记忆与日志/state.json 中的执行状态。

正规军效果对比：

  • 主动声明受控：AI 首先回复“受 AGENTS.md 资产红线约束，不会删除任何代码”，消除了误删风险；
  • 确定性计算：精准调用 Python 计算工具，百分比与金额完全准确；
  • 环境绝对纯净：中间清洗过程被妥善隔离，最终报告稳稳落入 交付成果/；根目录没有产生任何垃圾文件！

    • 用途：自动审查团队提交的 Python 代码风格并生成规范改进建议。
    • 资产参考：知识库放《PEP8编码规范精要.md》，脚本目录放代码行数与命名统计工具。
  • 赛道 B【新媒体运营向】：多模态爆款文案与图文违禁词自审 Agent
    • 用途：为图文营销生成草稿，并自动检测违禁词和图片比例。
    • 资产参考：知识库放《广告法禁用词与限流敏感词库.txt》，脚本目录放图片尺寸与大小校验脚本。
  • 赛道 C【综合行政向】：实训团队/社团经费报销合规初审 Agent
    • 用途：审核报销明细、校验发票真伪格式并统计各组剩余额度。
    • 资产参考：知识库放《社团经费管理条例.md》，脚本目录放发票金额求和与去重脚本。

操作①｜建立 5 核心项目目录树

在本地工作区新建项目文件夹，按照规范建立完整的目录拓扑，确保目录命名清晰、层级分明。

操作②｜根据所选赛道定制《AGENTS.md》

为你的智能体编写专属行为准则，必须包含以下三项：

  1. 明确的智能体角色名称与服务目标；
  2. 至少 2 条贴合该赛道业务的不可违背红线（如赛道 A 严禁自动覆盖原代码、赛道 C 严禁虚报金额）；
  3. 严格的产物隔离与目录访问规则（说明草稿放哪里、成品放哪里）。

操作③｜归置动静资产并初始化 state.json

  • 向 知识库/ 放入至少 1 份业务参考资料或模板；
  • 向 脚本与工具/ 放入至少 1 个可运行的辅助 Python 脚本；
  • 在 记忆与日志/state.json 中配置 1 组能体现“长期跨会话记忆”的业务状态（如历史违规次数、剩余预算或风格偏好）。

操作④｜执行一次自检测试

向智能体发出综合自检指令，验证智能体能否准确读懂 AGENTS.md，并在输出时遵循目录隔离规则。

成果检查标准（4 维物理指标）

检查维度 合格标准（满分） 不合格现象（扣分项）
根目录整洁度 根目录下仅有 AGENTS.md、README.md 与核心文件夹，无任何散落文件 根目录下堆放临时 txt、截屏、中间 json
宪法约束力 AGENTS.md 包含具体可执行的角色、红线与工具调用准则 只写“请扮演专业助手”一句空话，无安全红线
动静归属分类 代码（.py/.sh）全在脚本目录，规范参考（.md/.txt）全在知识库 在知识库里写 Python 代码，或在脚本仓库放业务说明
产物与状态隔离 正式成果在 final/，过程在 .temp/，state.json 记录提炼后的核心状态 把原始聊天记录当记忆，或把未校验草稿当成果交付
